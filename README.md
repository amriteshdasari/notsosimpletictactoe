# Not So Simple Tic-Tac-Toe

A tic-tac-toe game built with [Flutter](https://flutter.dev). You play as **X**; your
opponent is a computer that plays as **O** using a **minimax** algorithm, so a perfect
human play can only end in a draw.

## Features

- 3x3 board rendered as a responsive `GridView` of tappable cells
- Two-player turn loop: you place an **X**, then the computer answers with an **O**
- Winning detection for all rows, columns and both diagonals
- Tie detection when the board fills up
- Minimax opponent:
  - `evaluateBoard` scores a finished line as `+10` (O wins) / `-10` (X wins), 0 otherwise
  - `minimax` searches the game tree, maximizing for O and minimizing for X
  - after your move the computer replays the best move found by the search
- Win/loss/tie shown in an `AlertDialog` with a reset action
- **Reset Game** button (and the dialog's Reset action) clears the board for a new round

## Getting started

### Prerequisites

- [Flutter SDK](https://docs.flutter.dev/get-started/install) (Dart SDK `>=2.12.0 <3.0.0`)

### Run locally

```sh
flutter pub get
flutter run
```

### Web build

A `web/` directory is included, so a web build also works:

```sh
flutter build web
```

### Tests

```sh
flutter test
```

`test/widget_test.dart` contains the default Flutter widget test.

## Project structure

| Path | Purpose |
|---|---|
| `lib/main.dart` | App entry point; creates the `MaterialApp` and shows `HomePage` |
| `lib/HomePage.dart` | Game state and logic: board, turns, win/tie checks, minimax AI, UI |
| `lib/GameButton.dart` | Model for one board cell (id, label, background color, enabled state) |
| `lib/custom_dialog.dart` | Reusable `AlertDialog` with a single action (used for win/loss/tie + reset) |
| `test/widget_test.dart` | Default Flutter widget test |
| `android/`, `ios/`, `web/` | Platform shells generated by the Flutter tooling |

## How the game works

1. `HomePage` keeps the board as a 3x3 list of `'_'`, `'X'` or `'O'` and mirrors every
   move onto the nine `GameButton` widgets.
2. Tapping an empty cell plays it for the active player and hands over the turn.
3. `checkWinner` inspects the two players' occupied cell ids against all eight
   winning lines; on a hit, `checkWinner` raises the "Player 1 Won!" or
   "Computer Won!" dialog.
4. If no winner is found and every cell is filled, a "Game Tied!" dialog is shown.
5. Otherwise, when it is O's turn, `autoPlay` re-runs minimax from the current board
   and plays the best cell for O.
6. Resetting reinitializes the board and all nine buttons.
